# sample-creator

Приложение на Rust (GTK4 и Android) для разбора и разметки большого
количества аудиозаписей и нарезки из них сэмплов. Пользователь слушает запись, ставит
маркеры, выделяет регионы, даёт им имена и цвета. Нарезка не происходит сразу:
регионы остаются черновиками. Их можно просмотреть и прослушать все вместе,
вернуться к исходнику и поправить. Файлы создаются только по явной команде
«Экспортировать», в папку, которую пользователь выбирает в этот момент.

Главное — разметка и плановая нарезка. Обработка (громкость, компрессия,
шумодав) идёт вторым приоритетом.

## Сценарий

1. Подключаю рекордер, выбираю в дереве файл прямо с его карты.
2. Слушаю, ставлю маркеры, выделяю регионы, называю их. Всё сохраняется само.
3. Перехожу к следующему файлу и повторяю. Можно вернуться к любому файлу позже.
4. Открываю «Обзор регионов»: все выделенные регионы из всех файлов. Слушаю их,
   снимаю лишние, правлю имена, прыгаю в исходник подвинуть границы.
5. Когда всё устраивает, нажимаю «Экспортировать», выбираю папку, получаю файлы.

До шага 5 на диск не пишется ни одного аудиофайла.

## Принципы

- **Неразрушающая работа.** Исходные файлы никогда не изменяются.
- **Ничего не пишем рядом с исходниками.** Записи часто лежат прямо на карте
  рекордера, засорять её нельзя. Разметка, кэши и настройки живут только в XDG-
  каталогах приложения. Источники открываются только на чтение. Единственное
  исключение — по явному выбору пользователя: файл разметки
  `sample-creator.json` на носителе (см. «Файл разметки на носителе»).
- **Автосохранение.** Каждое изменение (маркер, регион, имя, цвет) сразу
  записывается в БД. Кнопки «Сохранить» нет. Вместо неё есть undo/redo.
- **Экспорт только явно.** Папка по умолчанию не задаётся. Пользователь выбирает
  её через диалог при каждом экспорте (последняя запоминается как подсказка).
- **Моно и стерео — полноценно.** По умолчанию число каналов сохраняется при
  экспорте, сведения в моно нет. Волна показывает каналы отдельными дорожками.
  Стерео-регион можно разложить на два моно-файла (L и R) или взять один канал.
- **Длинные записи — норма.** Файлы на несколько часов. Файл никогда не
  декодируется в память целиком, всё работает потоково.
- **Клавиатура в первую очередь.** Цикл «послушал → отметил → назвал → дальше»
  проходится без мыши.
- **Минимализм.** libadwaita, без лишних панелей, тёмная тема по умолчанию.
- **Сохранение формата.** 32-bit float на входе даёт 32-bit float на выходе,
  если не задано иное.

## Форматы

| Формат | Примечание |
|---|---|
| WAV (16/24-bit int, 32-bit float) | основной |
| BWF (Broadcast Wave) | тот же WAV плюс чанк `bext` (дата/время записи) и маркеры рекордера |
| MP3 | только чтение; экспорт из MP3 идёт в WAV |
| FLAC | добавить бесплатно, symphonia умеет |

### Пример: файл с портативного рекордера

Файл `261008_0065.wav` (15,12 с). Порядок чанков:

| Чанк | Содержимое |
|---|---|
| `bext` (1116 Б) | originator — модель рекордера, дата `2026-10-08`, время `22:47:55`, TimeReference = 3938686848 сэмплов от полуночи, description пустой |
| `cue ` (100 Б) | 4 точки; позиции в кадрах (`dwSampleOffset`), `fccChunk = "data"` |
| `LIST`/`adtl` | `labl` для каждой точки: `MARK_01`…`MARK_04` |
| `JUNK` (4172 Б) | резерв, пропускаем |
| `fmt ` | format tag 3 (IEEE float, не EXTENSIBLE), 2 канала, 48 kHz, 32 бит |
| `data` | 5 806 080 Б = 725 760 кадров |

Метки в примере:

| cue id | Позиция (кадры) | Время | Имя |
|---|---|---|---|
| 1 | 49 536 | 1,032 с | MARK_04 |
| 2 | 209 664 | 4,368 с | MARK_01 |
| 3 | 354 816 | 7,392 с | MARK_02 |
| 4 | 549 504 | 11,448 с | MARK_03 |

Выводы для реализации:

- **Маркеры — стандартные `cue ` + `adtl/labl`.** Импортируем их при первом
  открытии файла как обычные маркеры (с пометкой «от рекордера»). Номер в имени
  не совпадает с порядком на таймлайне, сортируем по позиции.
- **`fmt ` идёт после `bext`/`cue `/`LIST`/`JUNK`.** Парсер не должен
  рассчитывать на фиксированный порядок чанков.
- **symphonia не отдаёт `bext` и `cue `.** Метаданные читаем своим маленьким
  RIFF-парсером (`audio/bwf.rs`), symphonia используем только для сэмплов.
- **TimeReference** даёт абсолютное время начала записи. Его показываем в
  интерфейсе и пишем в `bext` экспортированных файлов со смещением региона.
  TimeReference (22:47:35.976) — начало записи; TimeReference + длительность
  15,12 с = 22:47:51, а поле `time` (22:47:55) — примерно момент закрытия файла.
  Показываем и используем TimeReference.

### Записи с рекордера: что ещё проверить
- **Парные файлы (4CH, Dual)** не используются, поддержку не делаем. Обычные
  режимы — моно и стерео.
- **Деление длинных записей.** При достижении лимита размера рекордер режет
  запись на последовательные файлы. Желательно уметь склеивать их в одну
  виртуальную дорожку.
- **Скорость чтения.** Чтение с карты через USB медленное (десятки МБ/с), а
  часовой файл 96 kHz / 32f / стерео весит около 2,7 ГБ. Воспроизведение должно
  начинаться сразу, волна достраивается в фоне.

## Стек

| Задача | Библиотека | Почему |
|---|---|---|
| UI | `relm4` + `gtk4` + `libadwaita` | компонентная модель с сообщениями; нативный GNOME-вид |
| Декодирование | `symphonia` | чистый Rust: WAV/BWF/MP3/FLAC, float32, seek |
| Воспроизведение | `cpal` + свой поток-плеер на symphonia | позиции с точностью до сэмпла для превью регионов и плейхеда; на NixOS идёт через ALSA → PipeWire |
| Запись WAV | свой writer поверх `hound`-подобной логики | нужно писать `bext`/`cue ` и RF64 для файлов > 4 ГБ |
| Хранилище | `rusqlite` (bundled) | одна БД на всю библиотеку, атомарные транзакции |
| Хэш файлов | `xxhash-rust` | опознание файла после переименования или копирования с рекордера |
| Каналы | `crossbeam-channel` | связь плеера и экспорта с UI |
| Обработка (позже) | свой DSP; `nnnoiseless` для шумодава речи | без тяжёлых зависимостей |

Волна — два `gtk::DrawingArea` (обзор и основная область) с рисованием через
cairo и общим состоянием в `Rc<RefCell<…>>` (`ui/waveform.rs`). Рисуется
залитым контуром min/max с гладкими краями (Catmull-Rom, `envelope` +
`fill_envelope`); при зуме глубже ячейки сводки (256 кадров) точки берутся по
одной на ячейку, без ступенек. На телефоне то же — `waveColumns` +
`fillEnvelope` в `mobile/lib/waveform.dart`. Ближе 64 кадров на пиксель
(`peaks::MIN_FRAMES_PER_PX`, ячейка ≤ 4 px) плавная волна не идёт.
Настройка «Подробная волна» (`waveform` / `mobile.waveform` = `detailed`):
столбец min/max на каждый пиксель с прямыми краями (`columns` +
`fill_columns`; на телефоне `wave_detail` и `fillEnvelope(smooth: false)`),
зум до 1 сэмпла на пиксель; ближе 256 кадров на пиксель сэмплы видимого
участка читаются из файла в фоне (`audio/detail.rs`: одно окно до 1 М кадров
с запасом по краям, пока оно не готово — рисуется сводка).
Настройка «Волна в децибелах» (`wave_scale` / `mobile.wave_scale` = `db`):
высота по `peaks::db_scale` (0 дБ — край дорожки, −60 дБ — средняя линия,
знак сохраняется), для основной волны и обзорной полосы; на телефоне —
`dbScale`/`shownColumnsOf` в `waveform.dart`. Редактор
опрашивает плеер и прогресс пиков в tick callback, без сообщений на каждый кадр.
Если cairo станет узким местом, можно перейти на subclass с `snapshot`.

## Сборка и окружение (NixOS, Wayland)

Разработка ведётся только через `flake.nix`. Глобального тулчейна в системе нет.

- `devShells.default`: `rustc`, `cargo`, `clippy`, `rustfmt`, `rust-analyzer`,
  `pkg-config`, `gtk4`, `libadwaita`, `alsa-lib`, `glib`, `wrapGAppsHook4`
  (для иконок и GSettings), `sqlite` не нужен (rusqlite bundled).
- `packages.default`: `rustPlatform.buildRustPackage` с `wrapGAppsHook4`, чтобы
  приложение запускалось как обычная программа.
- Wayland: GTK4 выбирает его сам. Диалог выбора папки — `gtk::FileDialog`, он
  работает через xdg-desktop-portal.
- Команды: `nix develop`, затем `cargo run [ПАПКА|ФАЙЛ]`; либо `nix run`.
- Утилиты для отладки: `cargo run --example inspect -- FILE` (метаданные, метки,
  пики), `--example play -- FILE START SECS` (плеер без UI),
  `--release --example peaks_bench -- FILE` (скорость расчёта волны),
  `--example share -- ПАПКА [QR.png]` (общий доступ к папке без интерфейса,
  тот же код, что у десктопа).

## Android (ветка `android`)

Логика без GTK вынесена в крейт `engine/` (`core`, `audio`, `store`, `dsp`,
`export`, `recording`), десктоп и телефон используют его одинаково.

- `mobile/` — Flutter-приложение; `mobile/rust/` — мост через
  flutter_rust_bridge (`api/engine.rs`: одна открытая запись, позиции в кадрах
  как `i64`, дешёвые вызовы `sync` опрашиваются каждый кадр).
- Окружение: `nix develop .#android` (Flutter, SDK 35/36, NDK 28.2, CMake
  3.22.1, Rust с Android-таргетами из rust-overlay).
- Сборка: `cd mobile && flutter build apk --release --split-per-abi --target-platform android-arm64`
  (→ `app-arm64-v8a-release.apk`; нативные библиотеки сжаты, `useLegacyPackaging`).
  Gradle сам собирает Rust через `cargo ndk` (задача `buildRust`, всегда release).
  После правок в `rust/src/api` — `flutter_rust_bridge_codegen generate`.
- Проверка моста без телефона: `cargo run -p sample_creator_bridge --example smoke -- FILE`.
- Файлы читаются по обычным путям: доступ «ко всем файлам»
  (`MANAGE_EXTERNAL_STORAGE`, канал `sample_creator/storage` в `MainActivity.kt`).
  Носители берутся из `StorageManager.getStorageVolumes()` (метод `volumes`),
  при монтировании/извлечении приходит `volumesChanged`. Рекордер или
  картридер по USB OTG — `/storage/<UUID>`, если Android его смонтировал.
- minSdk 26: cpal играет через AAudio. cpal нужен JNI-контекст: `MainActivity.onCreate`
  загружает библиотеку и вызывает `initAndroidContext` (`rust/src/android.rs`) до Dart.
- Ошибки запуска движка показываются на экране, а не оставляют вечную заставку.
- Проверка в эмуляторе (KVM): SDK с `includeEmulator`/`google_apis x86_64`,
  сборка с `--target-platform android-arm64,android-x64`, `adb install`.
- Интерфейс повторяет десктоп: вкладки «Разметка», «Обзор регионов»,
  «Обработка» (нижняя панель). Плеер общий: показанная вкладка забирает его,
  «Разметка» при возврате делает `reattach`.
- «Разметка»: боковая панель — файловая система по одной папке (как браузер),
  открытие записи не закрывает редактор. Долгое нажатие и ведение — выделение;
  щипок — зум; двойное касание — весь файл; тап — плейхед и выбор; ручки на
  краях выбранного региона или выделения тянутся пальцем; нижняя панель
  элемента: имя, цвет, экспорт, удаление.
- «Обзор регионов»: группы по записям, мини-волны, превью (с обработкой, если
  скорость изменена), фильтры, каналы, переименование, «в разметку»; экспорт
  в папку из своего выбора папок (с созданием новой), шаблон, формат, прогресс.
- «Обработка»: скорость и тон, ▶ оригинал / ▶ результат; быстрая нарезка
  прямо на вкладке и подробный режим на весь экран (`parts_editor.dart`):
  щипок — масштаб, касание — курсор и выбор части, края выбранной части
  тянутся снизу, фейды — кружками сверху; отмена/повтор (`RegionHistory`
  в мосте: `processing_undo`/`processing_redo`).
- Значок: `data/icons/…/io.github.horhik.SampleCreator.svg` (волна с
  выделенным регионом); на Android — адаптивная иконка (`res/drawable/
  ic_launcher_*.xml`, есть monochrome для тематических значков).
- Горизонтально: вкладки — узкая колонка слева (`NavigationRail`), волна на
  весь экран, управление — плавающая панель снизу по центру (прячется),
  маркеры и регионы — правая панель (кнопка в заголовке). В полноэкранном
  режиме заголовка нет: «Файлы», правая панель, отмена и повтор — вверху
  колонки вкладок (`markup_rail.dart`), имя записи — над списком в правой
  панели. Ползунок масштаба
  (логарифмический) есть в обеих ориентациях. «Полноэкранный режим» в боковой
  панели под носителями прячет системные панели (`display.dart`). В «Обзоре
  регионов» горизонтально фильтр и экспорт — в правой панели (скрывается).
- Тема: светлая/тёмная по системе, цвета Material You (`dynamic_color` 1.7.0:
  новые версии не собираются с Gradle-шаблоном Flutter 3.41).
- Вибрация: начало выделения, захват маркера или края, отпускание маркера;
  в нарезке — долгое нажатие поднимает часть.
- Горизонтально «Обработка»: список регионов — узкая колонка слева.
- Мост: `api/engine.rs` (открытая запись), `api/review.rs` (все записи,
  превью, экспорт через `StreamSink`), общее состояние в `state.rs`.
  Экспорт для обеих версий — `export::render_all` в движке.

- **Левая панель** (`GtkPaned`, ширина регулируется и запоминается): дерево
  каталогов, отфильтрованное по аудиофайлам. Рядом с файлом — счётчик регионов
  и статус: ● размечен, ✓ просмотрен. Подключённые носители (рекордер)
  показываются отдельным корнем.
- **Правая панель**: метаданные, обзорная полоса всего файла с рамкой видимой
  области, волна по каналам (L/R отдельно, можно свернуть в одну дорожку только
  для отображения), транспорт, список маркеров и регионов с редактированием на
  месте.
- **Место прослушивания запоминается.** Плейхед записывается в `files.position`
  (схема 8), когда ставят паузу, уходят на другую вкладку или открывают другую
  запись, и восстанавливается при возвращении. Это местная отметка, а не
  разметка: в файл на носителе она не синхронизируется.
- **Обработка** (третья вкладка): слева все регионы, справа настройки
  выбранного. Скорость: ползунок ×0,25…×4, кнопки ×0,5…×3, «Сохранять тон».
  Нарезка и склейка на ленте результата: части подряд на двух чередующихся
  дорожках. Убранная часть исчезает, соседи смыкаются. Часть тянется за
  середину (наложение на предыдущую или пауза, следующие едут вместе), за края
  (подрезка, звук остаётся на месте), за кружки сверху (фейды). Курсор — на
  ленте: «Разрезать» режет часть под ним, «Результат» играет с него.
  Фейды независимы от наложения; кроссфейд = наложение + равные фейды
  (equal-power). Длительность
  «было → станет», ▶ оригинал / ▶ результат. Всё сохраняется сразу; звук
  обрабатывается при прослушивании и экспорте (сначала склейка, потом скорость).
  Ctrl+колесо (или щипок на тачпаде) — масштаб волны нарезки, колесо —
  прокрутка, двойной щелчок — весь регион. Отмена/повтор правок обработки — `RegionHistory` (Ctrl+Z,
  Ctrl+Shift+Z, кнопки в заголовке), история общая для всех записей.
  Delete/Backspace убирает выбранную на ленте часть.
- **Обзор регионов** (вторая вкладка `AdwViewStack`): все регионы по всем
  файлам, сгруппированные по исходнику. Для каждого: мини-волна, имя,
  длительность, каналы, ▶ превью, «перейти к исходнику» (открывает файл во
  вкладке «Разметка» с выделенным регионом), чекбокс «в экспорт». Превью играет
  прямо из исходника, временные файлы не нужны. Внизу шаблон имени, формат и
  кнопка «Экспортировать…», которая открывает выбор папки.
- **Общая папка** (`engine/src/remote.rs`, `engine/src/vfs.rs`): правый клик
  по папке в дереве → «Поделиться папкой…» → диалог с QR-кодом и кодом
  `sc1.<токен>.<EndpointTicket>`. Кнопка в заголовке показывает, что доступ
  открыт, и закрывает его. Телефон сканирует код (`remote_ui.dart`,
  mobile_scanner), папка появляется в боковой панели рядом с носителями
  («Компьютер») и видна движку как путь `/sc-remote/<id>/…`: `vfs` отдаёт
  `open`/`metadata`/`read_dir` для локальных и удалённых путей, поэтому
  декодер, пики, отпечатки, кэш рендера и экспорт ничего не знают о сети.
  Протокол: iroh (ALPN `sample-creator/share/1`, n0-ретрансляторы и
  discovery), строка JSON на запрос (`list`/`stat`/`read`), чтение блоками по
  512 КБ с LRU. Токен проверяется на каждый запрос, пути не выходят за
  корень папки, только чтение. Ключ узла (`share.secret`) и токен папки
  (`share.token:<папка>`) хранятся в настройках, поэтому код папки постоянный
  и телефон переподключается сам (`mobile.remotes`).
  Запись перед открытием скачивается целиком (`remote::download`, 4 запроса
  по 2 МБ в полёте, окно с прогрессом `ensureLocal` в `remote_ui.dart`) в
  `cache/remote/<xxh3(id/путь)>_<размер>_<mtime>`; `vfs::open` берёт копию,
  если она совпадает с файлом на компьютере, а без связи — последнюю копию.
  Кэш до 4 ГБ, вытесняются давно открытые. Потоковое чтение по сети
  (`RemoteFile`) — для прослушивания и обзора без скачивания: блок по 512 КБ
  плюс 3 следующих параллельно; блоки, прочитанные подряд с начала, дописываются
  в `<копия>.part`, и скачивание продолжает с её конца (отмена её не удаляет).
  Долгое нажатие на запись в списке файлов — `preview_file` (играет с начала),
  отпускание — `stop_file_preview` (плеер возвращается к открытой записи).
  Устойчивость: плеер при смене источника прерывает чтения прежнего
  удалённого файла (`remote::interrupt_reads`), иначе команда загрузки ждёт
  сеть; подключение — 10 с, запрос — 30 с, после неудачного подключения
  запросы 10 с сразу получают отказ, повтор только при оборвавшемся
  соединении. Синхронные вызовы моста (из UI-потока) не должны ходить в сеть:
  для них `vfs::metadata_now` (последнее увиденное). Пики удалённой записи
  считаются только с локальной копии.
- Вывод звука: поток cpal живёт в своём потоке (`run_output` в
  `audio/player.rs`) и открывается заново на текущем устройстве по
  умолчанию, если устройство пропало (`DeviceNotAvailable`: Bluetooth,
  наушники) или во время игры 2 с не было колбэков; новая раскладка
  (каналы, частота) уходит декодеру `Cmd::Output`, игра идёт с плейхеда.
- Громкость прослушивания: `Player::set_monitor_db` (−24…+24 дБ, поверх
  громкости региона, не сбрасывается при загрузке, на экспорт не влияет);
  телефон — `listening.dart` (кнопка-динамик в транспорте, `mobile.listening_db`),
  десктоп — кнопка с ползунком в строке транспорта (`listening_db`).

### Палитра

Фиксированные 8 цветов, клавиши `1`–`8`. Цвету можно присвоить смысл (например
«ударные», «вокал», «мусор»), и тогда он работает как лёгкий тег и фильтр в
обзоре регионов.

### Горячие клавиши

Буквы работают по физической клавише, то есть и в русской раскладке. Пока
курсор стоит в поле имени, клавиши идут в поле. Внизу редактора всегда есть
строка подсказок для текущей ситуации, `?`/`F1` открывает полный список, а
правая кнопка на волне — меню со всеми действиями и их клавишами.

| Клавиша | Действие |
|---|---|
| `Space` | play/pause |
| `Home` | в начало |
| `←` / `→` | сдвиг плейхеда на 1 с (с `Shift` — на 10 с) |
| `M` | маркер в позиции плейхеда |
| `I` / `O` | начало/конец выделения в позиции плейхеда; если выбран регион — двигают его границу |
| drag по волне | выделение; drag за край региона или за маркер — сдвиг; drag за плашку региона — перенос целиком |
| клик | выбрать маркер/регион под курсором и поставить плейхед |
| `Shift`+клик | подрезать: край выделения (или выбранного региона), лежащий по ту же сторону от центра, переносится в точку клика |
| правая кнопка | меню: маркер здесь, регион, цвет, экспорт, удалить… с клавишами |
| двойной клик | переименовать |
| `R` | регион из выделения, сразу фокус на ввод имени |
| `Enter` / `F2` | переименовать выбранный маркер или регион |
| `1`–`8` | цвет выбранного (и цвет для следующих новых) |
| `E` | переключить «в экспорт» |
| `C` | автоцикл вкл/выкл: выделение, а если его нет — выбранный регион, играют по кругу (по умолчанию включён) |
| `Del` / `Backspace` | удалить выбранный |
| `Tab` / `Shift+Tab` | следующий/предыдущий маркер или регион |
| `J` / `K` | следующая/предыдущая запись в той же папке (то же — `Ctrl+Tab` / `Ctrl+Shift+Tab`) |
| `L` / `H` | следующая/предыдущая папка; открывается первая запись в ней |
| `Ctrl+L` / `Ctrl+H` | следующий/предыдущий регион |
| `Ctrl+J` / `Ctrl+K` | следующий/предыдущий маркер |
| `Esc` | снять выделение и выбор |
| `?` / `F1` | памятка со всеми клавишами |
| `Ctrl+колесо`, `+`/`-`, `0` | зум, весь файл; колесо — прокрутка; щипок двумя пальцами на тачпаде — тоже зум (`GtkGestureZoom`, вокруг пальцев) |
| `Ctrl+Z` / `Ctrl+Shift+Z`, `Ctrl+Y` | undo/redo (история своя у каждого файла, живёт до закрытия) |

## Модель данных

```rust
struct SourceFile {
    id: FileId,
    path: PathBuf,           // последний известный путь
    alias: Option<String>,   // своё имя записи вместо имени файла (клик по заголовку)
    fingerprint: u64,        // xxhash(size + первые/последние 1 МБ) — дёшево даже по USB
    sample_rate: u32,
    channels: u16,
    format: SampleFormat,    // I16 | I24 | I32 | F32
    length_frames: u64,
    recorded_at: Option<DateTime>, // из bext
    reviewed: bool,
}

struct Marker { id, file: FileId, pos: u64 /* frames */, name: String, color: ColorIdx }

struct Region {
    id, file: FileId,
    start: u64, end: u64,    // frames, не секунды: без ошибок округления
    name: String,
    color: ColorIdx,
    export: bool,            // отмечен к экспорту; по умолчанию true
    channels: ChannelMode,   // AsSource | Left | Right | SplitMono
    speed: u16,              // в процентах, 100 = ×1; 25..=400
    keep_pitch: bool,        // time-stretch вместо «пластинки»
    parts: Vec<Part>,        // нарезка: части по порядку на ленте результата; пусто = весь регион
    // Part { start, end (кадры записи), fade_in, fade_out, overlap: i64 —
    //        наложение на предыдущую часть, < 0 — пауза }
    fx: FxChain,             // gain, fade in/out, normalize… (позже)
    last_export: Option<ExportRecord>, // куда и когда; видно, если регион менялся после
}
```

Все позиции хранятся в кадрах (frames) исходного файла. Секунды получаются
только при отображении.

### Хранение

Всё хранится только у приложения, рядом с записями — ничего:

- разметка: SQLite в `$XDG_DATA_HOME/sample-creator/library.db`;
- кэш пиков: `$XDG_CACHE_HOME/sample-creator/peaks/<fingerprint>`;
- настройки (ширина панели, последний каталог экспорта): `$XDG_CONFIG_HOME`.

Файл опознаётся по `fingerprint`. Если перенести запись с рекордера на диск,
разметка подхватится автоматически.

Каждое действие пользователя — это команда (`AddRegion`, `RenameRegion`,
`MoveRegionEdge`…). Она применяется к состоянию, пишется в БД одной транзакцией
и кладётся в undo-стек. Перетаскивания склеиваются в одну команду при
отпускании мыши.

### Кэш пиков

Пики (min/max на канал) считаются на двух уровнях: 256 и 16384 кадров на бин.
Расчёт идёт в фоновом потоке, файл читается последовательно, волна
дорисовывается по мере готовности. Трёхчасовой файл 96 kHz даёт около 16 МБ
кэша на канал на мелком уровне, это приемлемо. На сильном зуме сэмплы читаются
прямо из файла.

### Память

Ни один компонент не держит файл целиком. Плеер читает кусками в ring buffer.
Экспорт копирует диапазон потоково. Мини-волны в обзоре регионов берутся из
кэша пиков.

Плеер шлёт позицию в UI через канал, UI обновляет плейхед в tick callback

работает в отдельном потоке (relm4 `Worker`) с прогрессом и отменой.

## Файл разметки на носителе

Чтобы разметка ездила с рекордером между устройствами (`engine/src/sync.rs`).

- Включается для носителя явно: на телефоне — меню ⋮ у носителя в боковой
  панели, на десктопе — кнопка синхронизации в заголовке (для корня дерева).
  «Создать в корне», «Создать в папке…», «Указать существующий…» (выбирается
  папка с файлом), затем «Синхронизировать сейчас» / «Отключить».
- Формат: JSON `sample-creator.json`; записи по отпечатку (16 hex), пути
  относительно корня носителя; маркеры, регионы, части, псевдоним, флаги.
- Синхронизация двусторонняя, по каждой записи побеждает более поздняя правка
  (`files.updated_at`, схема v6; импорт меток рекордера время не трогает, так
  что нетронутая запись никогда не перетирает чужую). Удаления переносятся,
  потому что разметка записи заменяется целиком. Нетронутые записи в файл не
  пишутся. Запись атомарная (`.part` + rename).
- Автоматически: при подключении носителя / выборе папки, при смене записи,
  при уходе приложения в фон (десктоп — при закрытии окна). Настройки — в
  `settings` (`sync.target:<корень>` → папка, `sync.last:<корень>`).
- После импорта истории отмены сбрасываются (id регионов новые).

## Экспорт

- Запускается только явно, из «Обзора регионов». Папку пользователь выбирает
  в диалоге.
- Шаблон имени: по умолчанию `{name}`. Без имени — `{source}_{index:02}`.
  Доступны `{color}`, `{date}`, `{source}`.
- Коллизии решаются суффиксом `_2`, `_3` или подтверждением перезаписи.
- Опционально подпапки по цвету-тегу: `{dest}/{tag}/`.
- Формат: «как у источника» (по умолчанию), WAV 24-bit или WAV 32f.
- Каналы задаются на регион (`ChannelMode`): как у источника (по умолчанию),
  только L, только R, или «разделить» — два моно-файла `{name}_L` и `{name}_R`.
  Сведения в моно нет. В обзоре регионов режим виден и переключается.
- В выходной BWF пишется `bext`: origin = исходный файл, time reference =
  смещение региона. Так всегда можно найти, откуда сэмпл.
- Опции против щелчков: привязка границ к ближайшему нулю и микро-фейд 2–5 мс.
- Регион помнит, что уже экспортирован и куда. В обзоре видно, какие регионы
  изменились после экспорта.

Интерфейс на русском и английском. Строки пишутся парами прямо в коде:
`tr("рус", "eng")` (Rust, `engine::lang`) и `tr('рус', 'eng')` (Dart,
`mobile/lib/l10n.dart`). Язык по умолчанию — системный (`LANG`/`LC_*` на
десктопе, локаль Android), выбор хранится в `settings` (`language` /
`mobile.language`: system, en, ru). Десктоп читает язык один раз при старте
(смена — после перезапуска), телефон пересоздаёт интерфейс сразу. Тексты
движка (цвета, форматы, ошибки) следуют `lang::set_russian`.

## Решения

- UI-фреймворк: relm4.
- Разметка хранится только в БД приложения, никаких файлов рядом с записями.
- Папки экспорта по умолчанию нет. Экспорт только явный, после обзора.
- Каналы при экспорте не сводятся. Стерео остаётся стерео, но его можно
  разделить на два моно-файла или взять один канал.
- Режимы записи: моно и стерео. 4CH и Dual не поддерживаем.
- Записям можно давать псевдонимы; при экспорте `{source}` берёт псевдоним,
  если он есть.
- Записи до нескольких часов: всё потоково. Исключение — обработка: регион
  (секунды–минуты) обрабатывается в памяти целиком.
- Скорость региона: режим «пластинки» и режим с сохранением тона, выбирается
  переключателем.
- `[profile.dev]` с оптимизацией: DSP и расчёт пиков без неё слишком медленные.
- Окружение: NixOS + Wayland, разработка через `flake.nix`.
- Android: Flutter + flutter_rust_bridge поверх общего крейта `engine`;
  без permission_handler (его Gradle-скрипты не совместимы с шаблоном Flutter 3.41).
- Общая папка: iroh (без своего сервера, работает через NAT), с компьютера
  на телефон, только чтение, без синхронизации. Разметка удалённых записей
  живёт в БД телефона. iroh без default features, `tls-ring`: без
  platform-verifier, которому на Android нужна инициализация из Kotlin.
